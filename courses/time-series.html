Module 0: What Is a Time Series?

0.1 Definition

A time series is a set of observations recorded in time order, usually at regular intervals: daily temperature, monthly sales, hourly electricity demand, daily website visitors.

The key difference from ordinary tabular data is that order matters and observations are not independent. Today's temperature is related to yesterday's. This dependence is what we model, and it is also why ordinary methods (random train/test splits, plain cross-validation) fail.

0.2 Two goals

Goal Question Example
Analysis What structure does the data have? Is traffic lower on weekends? Is there a trend?
Forecasting What will happen next? How many visitors tomorrow?

Analysis helps forecasting: understanding the structure lets you choose a better model.

0.3 Types of series

  • Univariate: one variable over time (daily temperature).
  • Multivariate: several variables over time (temperature, humidity, pressure).
  • Regular vs irregular: regular series have fixed spacing (daily); irregular ones do not (sensor events).
  • Continuous vs count: temperature is continuous; visitor counts are non-negative integers, usually right-skewed.

0.4 Frequency and horizon

  • Frequency: how often data is recorded (hourly, daily, weekly, monthly, quarterly, yearly).
  • Forecast horizon (h): how far ahead you forecast. "Next 7 days" means h = 7.
  • Short horizons rely on recent values; long horizons rely on seasonality and trend. Accuracy usually falls as the horizon grows.

0.5 The forecasting workflow

  1. Define the problem: what is forecast, at what frequency, how far ahead, and how will it be used?
  2. Collect and clean the data: datetime index, missing values, abnormal values.
  3. Explore: plots, seasonality, trend, stationarity, autocorrelation.
  4. Split chronologically into training and test data. (Do this before exploring too deeply, so the test data cannot influence your choices.)
  5. Build baselines, then models. Always beat the simple methods first.
  6. Evaluate on data the model has not seen. Check residuals.
  7. Forecast the future with prediction intervals.
  8. Communicate results, assumptions and limits.
  9. Monitor and update as new data arrives.

0.6 Forecasts are never certain

A forecast is an estimate of a distribution of future values. Good forecasting reports a central value and the uncertainty around it.

Module 1: Working with Time Data in pandas

1.1 Datetime and the index

Most raw files store dates as text. Convert them, sort, and make the date the index:

import pandas as pd

df = pd.read_csv("sales.csv")
df["date"] = pd.to_datetime(df["date"])
df = df.sort_values("date").set_index("date")

A DatetimeIndex unlocks time-based slicing:

df.loc["2024-03"]              # all of March 2024
df.loc["2024-01-01":"2024-03-31"]
df.index.dayofweek             # 0 = Monday
df.index.day_name()
df.index.month

1.2 Frequency

Most models need a regular, gap-free index with a declared frequency:

expected = pd.date_range(df.index.min(), df.index.max(), freq="D")
missing_days = expected.difference(df.index)   # which dates are absent?
df = df.asfreq("D")                            # missing days become NaN

Common frequency codes: D day, W week, MS month start, ME month end, QS quarter start, YS year start, h hour. (In recent pandas versions, M was replaced by ME.)

1.3 Resampling

Resampling changes the frequency. You must choose an aggregation that matches the meaning of the variable:

Variable type Aggregation Example
Amounts (sales, visits, rainfall) sum for totals, mean for typical level weekly total sales
Levels or intensities (temperature, price) mean (or last value for prices) monthly average temperature
Extremes max or min daily peak demand 
weekly_total = df["sales"].resample("W").sum()
monthly_mean = df["sales"].resample("MS").mean()

Pitfall: the first and last periods may be incomplete (a partial week or month). Count the observations per period and drop incomplete ones.

1.4 Shifts, differences and rolling windows

df["sales"].shift(7)                    # value 7 rows earlier (a lag)
df["sales"].diff()                      # y(t) - y(t-1)
df["sales"].diff(7)                     # y(t) - y(t-7): seasonal difference
df["sales"].pct_change()                # percentage change
df["sales"].rolling(window=7).mean()    # 7-day moving average
df["sales"].rolling(window=30).std()    # rolling variability
df["sales"].expanding().mean()          # mean of everything up to now

A rolling mean smooths noise. A window equal to the seasonal period (7 for weekly data) averages out the seasonal pattern, leaving the level.

1.5 Missing values

Do not fill blindly. Ask why the value is missing.

Situation Reasonable action
Isolated gap in a smooth series time interpolation (interpolate(method="time"))
Gap in a strongly seasonal series interpolate using the same season, or a seasonal method
Long gap do not invent data; split the series or model the gap
Measurement error (impossible value) set to missing first, then decide
Missing means zero (no sales) fill with 0

Never use bfill (backward fill) on data you will forecast with, because it uses future values to fill the past.

1.6 Real-world cleaning checklist

  • Numbers stored as text with commas ("2,146"): remove commas, convert with pd.to_numeric.
  • Dates in an ambiguous format (03/04/2024): set dayfirst explicitly.
  • Duplicate dates, unsorted rows.
  • Impossible values (negative counts, pressure of 7,000 hPa): flag them.
  • Two files that overlap in time: check shared dates and decide which version to keep. One suspicious row at the end of a training set can distort every model that depends on recent values.

Module 2: Trend, Seasonality, Noise and Decomposition

2.1 The components

Component Meaning Example
Trend long-term upward or downward movement traffic growing over several years
Seasonality a pattern that repeats at a fixed, known period lower traffic every weekend; hot every summer
Cycle rises and falls with no fixed period economic booms and recessions
Noise (residual) irregular, unexplained variation random day-to-day variation

Seasonality vs cycle: seasonality has a known, constant period (7 days, 12 months). Cycles have varying length. This difference matters because seasonal models need a known period.

A series can have several seasonalities at once, for example weekly and yearly in daily data.

2.2 Additive vs multiplicative

  • Additive: y = trend + seasonal + noise. The seasonal swing has a constant size (always ±8 °C).
  • Multiplicative: y = trend × seasonal × noise. The swing grows with the level (a busy period has bigger weekly swings).

How to tell: if the seasonal swings get larger as the level rises, the series is multiplicative. A log transform turns a multiplicative series into an additive one:

log(trend × seasonal × noise) = log(trend) + log(seasonal) + log(noise)

A quick check: plot rolling standard deviation against rolling mean. A strong positive relationship suggests a multiplicative pattern.

2.3 Decomposition

Decomposition splits a series into trend, seasonal and residual parts.

from statsmodels.tsa.seasonal import seasonal_decompose, STL

# Classical decomposition (needs the period)
result = seasonal_decompose(y, model="additive", period=7)
result.plot()

# STL: more flexible, robust to outliers, seasonal shape can change slowly
stl_result = STL(y, period=7, robust=True).fit()
stl_result.plot()
Method Strengths Weaknesses
Classical simple, fast trend missing at both ends; seasonal shape fixed; not robust to outliers
STL handles changing seasonality, robust option, any period additive only (use log for multiplicative)

Rule for the period: daily data with weekly pattern → 7; monthly data with yearly pattern → 12; hourly data with daily pattern → 24. For a long period such as 365 in daily data, decompose the weekly or monthly averages instead (period 52 or 12), where the pattern is clearer.

2.4 Strength of seasonality and trend

A useful summary (Hyndman and Athanasopoulos):

def strength(decomposition):
    resid = decomposition.resid.dropna()
    seasonal = decomposition.seasonal.loc[resid.index]
    trend = decomposition.trend.loc[resid.index]
    seasonal_strength = max(0, 1 - resid.var() / (resid + seasonal).var())
    trend_strength = max(0, 1 - resid.var() / (resid + trend).var())
    return seasonal_strength, trend_strength

Values run from 0 (none) to 1 (very strong). A seasonal strength above about 0.64 is a commonly used threshold for applying seasonal differencing.

2.5 Why this matters

Decomposition tells you how much of the variation is predictable (trend and seasonality) versus unpredictable (noise). If most variation is seasonal, a seasonal model is essential. If noise dominates, even the best model has limited accuracy.

Module 3: Exploring a Series Visually

Plots are the main tool for understanding a series. Make them before running any test or model.

3.1 The essential plots

Plot Shows What to look for
Line plot the whole series trend, level shifts, spikes, gaps, season
Rolling mean smoothed level trend; use a window equal to the season to remove it
Rolling std changing variability variance growing with level
Histogram / KDE distribution skew, several humps (regimes)
Box plot by calendar part seasonal pattern differences between weekdays or months
Seasonal plot each year/week overlaid how the seasonal shape changes
Heatmap (weekday × month) two calendar effects together whether the weekly pattern changes during the year
Lag plot y(t) vs y(t-k) autocorrelation at lag k 
import matplotlib.pyplot as plt
import seaborn as sns

fig, ax = plt.subplots(figsize=(12, 5))
ax.plot(y, color="lightgrey", label="Daily")
ax.plot(y.rolling(7).mean(), label="7-day mean")
ax.plot(y.rolling(30).mean(), label="30-day mean")
ax.set_title("Daily visitors with rolling means")
ax.set_xlabel("Date"); ax.set_ylabel("Visitors")
ax.legend()
plt.tight_layout()
plt.show()

3.2 Calendar patterns

calendar = pd.DataFrame({"y": y})
calendar["weekday"] = y.index.day_name()
calendar["month"] = y.index.month
sns.boxplot(data=calendar, x="weekday", y="y")

Only analyse patterns that make sense for your data. Temperature has no weekday effect; website traffic does. Test an assumption quickly (compare weekday and weekend means) rather than assuming.

3.3 Plot design rules

  • Label axes with units and give every plot a title.
  • Use consistent figure sizes.
  • Do not hide gaps; show them.
  • When comparing years, use only complete years.

3.4 Reading a line plot: a checklist

  1. Is there a trend? Up, down, or changing?
  2. Is there a repeating pattern? At what period?
  3. Does the pattern's size change with the level?
  4. Are there level shifts (the series jumps to a new range and stays)?
  5. Are there outliers or gaps? Are they errors or real events?
  6. Does the variability change over time?

Module 4: Stationarity and Differencing

4.1 Why stationarity?

A series is weakly stationary if:

  • its mean is constant over time,
  • its variance is constant over time,
  • its autocorrelation depends only on the lag between points, not on when they occur.

Trend breaks the first condition. Seasonality breaks it too (the mean depends on the season). Models in the ARIMA family are built for stationary data (after differencing), because they assume the relationships learned from the past still hold in the future.

4.2 Two special series

  • White noise: independent values with constant mean and variance. It is stationary and unpredictable: the best forecast is its mean. If your model residuals are white noise, the model has captured the predictable structure.
  • Random walk: y(t) = y(t-1) + noise. It is non-stationary. Its best forecast is the last value (the naive forecast). Its differences, y(t) - y(t-1), are white noise.

Many financial and level-like series behave like random walks, which is why the naive forecast is hard to beat for them.

4.3 Tests for stationarity

ADF (Augmented Dickey-Fuller)

  • H0: the series has a unit root (non-stationary).
  • H1: the series is stationary.
  • p < 0.05 → reject H0 → evidence of stationarity.

KPSS

  • H0: the series is stationary (opposite of ADF).
  • p < 0.05 → reject H0 → evidence of non-stationarity.
from statsmodels.tsa.stattools import adfuller, kpss

adf_p = adfuller(y.dropna(), autolag="AIC")[1]
kpss_p = kpss(y.dropna(), regression="c", nlags="auto")[1]

Use both together:

ADF KPSS Conclusion
rejects H0 does not reject stationary
does not reject rejects H0 non-stationary → difference
rejects rejects trend-stationary or conflicting; investigate, use plots
does not reject does not reject inconclusive; low power or short data

Caution: ADF detects a stochastic trend (unit root). It is weak against strong deterministic seasonality. A strongly seasonal series can pass the ADF test and still not be stationary. Always combine the test with plots and seasonal-strength measures.

4.4 Making a series stationary

Transformations (for changing variance)

  • Log: turns multiplicative patterns into additive ones. For counts with zeros use log1p.
  • Box-Cox: a family of power transforms; λ = 0 equals the log.
import numpy as np
y_log = np.log1p(y)        # forecast on this scale, then back-transform with np.expm1

A forecast back-transformed from log scale is approximately the median, not the mean, so it can be slightly low.

Differencing (for changing mean)

  • First difference: y(t) − y(t−1) removes a trend or unit root.
  • Seasonal difference: y(t) − y(t−m) removes a seasonal pattern with period m (7 for weekly).
  • Applying both: y.diff(m).diff().
y_diff = y.diff().dropna()
y_seasonal_diff = y.diff(7).dropna()
y_both = y.diff(7).diff().dropna()

How much differencing?

  • Use as little as possible. Typically d is 0 or 1; d = 2 is rare.
  • Over-differencing introduces artificial negative autocorrelation and makes forecasts noisier. Signs: the differenced series has a very strong negative spike at lag 1 in the ACF, and its variance is larger than before.
  • Choose by documented rules (for example: seasonal difference if seasonal strength > 0.64; first difference if ADF fails) before looking at model scores.

4.5 Interpreting differenced forecasts

An ARIMA model with d = 1 forecasts the differences and then adds them back up. Without a constant, a long-horizon forecast becomes nearly flat at the last level; this is why a non-seasonal ARIMA can do badly over many steps on a seasonal series.

Module 5: Autocorrelation: ACF and PACF

5.1 Ideas

  • Lag: a time shift. Lag 1 compares each value with the previous one.
  • Autocorrelation (ACF) at lag k: the correlation between y(t) and y(t−k), including indirect effects through the lags in between.
  • Partial autocorrelation (PACF) at lag k: the correlation between y(t) and y(t−k) after removing the effect of lags 1 to k−1. It isolates the direct link.
from statsmodels.graphics.tsaplots import plot_acf, plot_pacf

fig, axes = plt.subplots(1, 2, figsize=(12, 4))
plot_acf(y_stationary, lags=40, ax=axes[0], zero=False)
plot_pacf(y_stationary, lags=40, ax=axes[1], zero=False, method="ywm")
plt.tight_layout(); plt.show()

The shaded band is an approximate 95% confidence limit: spikes outside it are statistically meaningful. About 1 in 20 spikes will cross the band by chance.

5.2 Reading patterns

Pattern What it suggests
ACF decays very slowly non-stationary: difference
ACF with repeating spikes at lag m, 2m, 3m seasonality with period m
Stationary series: PACF cuts off after lag p, ACF decays gradually AR(p)
Stationary series: ACF cuts off after lag q, PACF decays gradually MA(q)
Both decay gradually ARMA (mixed)
Strong negative spike at lag 1 after differencing possible over-differencing, or an MA(1) term
Spike at lag m only (ACF) seasonal MA term
Spike at lag m only (PACF) seasonal AR term

Treat these as guides, not rules. Real data is messy. Use them to choose a small set of candidate models, then compare them with AIC and out-of-sample error.

5.3 Testing whether a series (or residual) is white noise

The Ljung-Box test:

  • H0: no autocorrelation up to the chosen lag.
  • A small p-value means there is leftover structure.
from statsmodels.stats.diagnostic import acorr_ljungbox
acorr_ljungbox(residuals, lags=[7, 14, 21])

For seasonal data, check lags that are multiples of the period.

Module 6: Splitting, Baselines, Metrics and Validation

6.1 The chronological split

test_size = 90
train = y.iloc[:-test_size]
test = y.iloc[-test_size:]

Never shuffle. A random split lets the model train on the future and be tested on the past, giving unrealistically good scores. This is data leakage.

Common leakage sources in time series:

  • random splitting or ordinary k-fold cross-validation,
  • fitting a scaler or imputer on the full series,
  • using bfill, centred rolling windows or interpolation that crosses the split,
  • choosing a transformation or order after looking at the test results,
  • features that use future information (for example a centred moving average).

Do all exploration and parameter selection on the training data only.

6.2 Baselines

A baseline tells you how hard the problem is. A complex model is only worthwhile if it beats them.

Method Rule Good for
Mean average of the training data stable series
Naive last observed value random-walk-like series
Seasonal naive value from one season earlier strong, stable seasonality
Drift line from first to last observation steady trend
Seasonal mean average of the same position in several recent seasons noisy seasonality

6.3 Error metrics

Let e(t) = actual − forecast.

Metric Formula idea Notes
MAE mean of ` e
RMSE square root of mean of e² punishes large errors; always ≥ MAE
MAPE mean of ` e
sMAPE symmetric version still unstable near 0; debated
Bias (ME) mean of e positive = under-forecasting on average
MASE MAE ÷ MAE of the in-sample naive forecast scale-free; < 1 means better than naive; good for comparing series 
import numpy as np

def mase(actual, forecast, train, m=1):
    """Mean absolute scaled error; m = seasonal period (1 for non-seasonal naive)."""
    train = np.asarray(train, dtype=float)
    scale = np.mean(np.abs(train[m:] - train[:-m]))
    return np.mean(np.abs(np.asarray(actual) - np.asarray(forecast))) / scale

Choosing a metric: use MAE if you want a typical error; RMSE if large misses are costly; MASE to compare across series of different scales; avoid MAPE for data with zeros or for temperature in Celsius.

6.4 Multi-step forecasts

  • One-shot (multi-step) forecast: forecast the whole test window at once from one origin. Tests long-range ability.
  • One-step-ahead forecast: refit or update after each new observation.
  • Report the horizon with every error number. "RMSE 240" means nothing without "at 14 days ahead".

6.5 Rolling-origin evaluation (time-series cross-validation)

One test window can be lucky or unlucky. A rolling-origin evaluation moves the forecast origin forward and repeats:

origin 1:  train [............]  forecast [h days]
origin 2:  train [..............]  forecast [h days]
origin 3:  train [................]  forecast [h days]

def rolling_origin(y, forecaster, test_start, horizon, step):
    errors = []
    for start in range(test_start, len(y) - horizon + 1, step):
        history = y.iloc[:start]                 # only the past
        actual = y.iloc[start:start + horizon]
        forecast = forecaster(history, actual.index)
        errors.append(actual - forecast)
    return pd.concat(errors)

Scikit-learn's TimeSeriesSplit does this for ML models with an expanding window:

from sklearn.model_selection import TimeSeriesSplit
tscv = TimeSeriesSplit(n_splits=5, test_size=14)
for train_idx, test_idx in tscv.split(X):
    ...

Rolling-origin results are more reliable than a single hold-out because they average over several forecast windows.

6.6 Residual diagnostics

For a good model, residuals should be:

  1. Mean zero (no bias),
  2. No autocorrelation (Ljung-Box, ACF plot),
  3. Constant variance over time,
  4. Roughly normal (needed mainly for prediction intervals).

If residuals still show structure, the model is missing information.

Module 7: Simple Forecasting Methods

These are not "toy" methods. On many real series they are hard to beat, and they are always the first thing to try.

7.1 The methods

import numpy as np
import pandas as pd

def naive(history, index):
    return pd.Series(history.iloc[-1], index=index)

def moving_average(history, index, window=7):
    return pd.Series(history.iloc[-window:].mean(), index=index)

def seasonal_naive(history, index, period=7):
    # most recent observed value for the same position in the season
    last = history.index[-1]
    cycles = np.ceil((index - last).days / period).astype(int)
    lookup = index - pd.to_timedelta(cycles * period, unit="D")
    return pd.Series(history.reindex(lookup).to_numpy(), index=index)

def drift(history, index):
    slope = (history.iloc[-1] - history.iloc[0]) / (len(history) - 1)
    steps = np.arange(1, len(index) + 1)
    return pd.Series(history.iloc[-1] + slope * steps, index=index)

7.2 What each assumes

Method Assumes
Mean no trend, no season; the long-run average is the best guess
Naive the latest value is the best guess (random walk)
Moving average the recent level is the best guess; noise is averaged out
Seasonal naive the seasonal pattern repeats exactly
Seasonal mean the seasonal pattern repeats; noise is averaged out across seasons
Drift steady linear change

7.3 Lessons

  • A seasonal series makes non-seasonal baselines look poor. Use the seasonal versions.
  • A flat forecast (naive, moving average) cannot follow a seasonal swing over many steps.
  • If a complicated model barely beats seasonal naive, the added complexity may not be worth it.

Module 8: Exponential Smoothing

8.1 The idea

Exponential smoothing forecasts using a weighted average of past values where recent observations get more weight, and weights decay exponentially into the past. It adapts to changing levels.

8.2 Simple exponential smoothing (SES)

level(t) = α · y(t) + (1 − α) · level(t−1), with 0 < α < 1.

  • α near 1: the level follows the data closely (fast adaptation, noisy).
  • α near 0: the level changes slowly (smooth, slow to adapt).
  • Forecast: a flat line at the latest level. Use for data without trend or seasonality.

8.3 Holt's linear method

Adds a trend component with its own smoothing parameter β. Forecasts continue the trend line.

Damped trend: the trend flattens out over the horizon. Damped trend forecasts are often more accurate than undamped ones because trends rarely continue forever.

8.4 Holt-Winters (seasonal)

Adds a seasonal component with parameter γ. Two versions:

  • Additive seasonality: constant seasonal swing.
  • Multiplicative seasonality: swing proportional to the level.
from statsmodels.tsa.holtwinters import ExponentialSmoothing

model = ExponentialSmoothing(
    train,
    trend="add",
    damped_trend=True,
    seasonal="add",              # or "mul" for positive data with growing swings
    seasonal_periods=7,
    initialization_method="estimated",
)
fitted = model.fit()
forecast = fitted.forecast(len(test))

8.5 The ETS framework

ETS names a model by its Error, Trend and Seasonal types: ETS(error, trend, seasonal) with options A (additive), M (multiplicative), N (none). Example: ETS(A, Ad, A) = additive error, damped additive trend, additive seasonality. Statsmodels provides ETSModel, which also gives prediction intervals and AIC for model comparison.

8.6 Strengths and limits

  • Strengths: simple, fast, robust, good for short series, adapts to level changes.
  • Limits: a seasonal period such as 365 in daily data is not practical; no external variables; one seasonality only.

Module 9: ARIMA

9.1 The building blocks

  • AR(p) — AutoRegressive: y(t) depends on its own last p values. y(t) = c + φ1·y(t−1) + … + φp·y(t−p) + e(t)
  • MA(q) — Moving Average: y(t) depends on the last q forecast errors. y(t) = c + e(t) + θ1·e(t−1) + … + θq·e(t−q)
  • I(d) — Integrated: difference the series d times to make it stationary.

ARIMA(p, d, q) = difference d times, then fit an ARMA(p, q) model.

9.2 Reading the notation

Model Meaning
ARIMA(0,0,0) white noise
ARIMA(0,1,0) random walk
ARIMA(1,0,0) first-order autoregression
ARIMA(0,1,1) simple exponential smoothing (equivalent)
ARIMA(1,1,1) difference once, one AR term, one MA term

A constant in a model with d = 0 sets the mean; with d = 1 it creates a drift. Statsmodels' ARIMA includes a constant by default only when d = 0.

9.3 Choosing the orders

  1. Choose d with plots and stationarity tests (Module 4).
  2. Look at ACF/PACF of the differenced series (Module 5) for candidate p and q.
  3. Compare a small grid with AIC (or AICc/BIC): lower is better. AIC rewards fit and penalises the number of parameters.
  4. Check residuals of the best candidates.
  5. Compare out of sample against baselines.

AIC is only comparable between models fitted to the same data with the same d.

Avoid searching hundreds of combinations: a larger search finds patterns that exist only in your training data (overfitting), and is hard to explain.

from statsmodels.tsa.statespace.sarimax import SARIMAX

def rank_by_aic(y, d, max_p=2, max_q=2):
    rows = []
    for p in range(max_p + 1):
        for q in range(max_q + 1):
            trend = "c" if d == 0 else "n"
            fitted = SARIMAX(y, order=(p, d, q), trend=trend).fit(disp=False)
            rows.append({"order": (p, d, q), "AIC": fitted.aic})
    return pd.DataFrame(rows).sort_values("AIC").reset_index(drop=True)

9.4 Fitting and forecasting

from statsmodels.tsa.arima.model import ARIMA

fitted = ARIMA(train, order=(1, 1, 1)).fit()
print(fitted.summary())

prediction = fitted.get_forecast(steps=len(test))
forecast = prediction.predicted_mean
interval = prediction.conf_int(alpha=0.05)     # 95% prediction interval

9.5 Behaviour of ARIMA forecasts

  • With no seasonal terms, a long-horizon forecast converges to a constant (for d = 0) or to a line / flat level (for d = 1). It cannot reproduce a repeating pattern.
  • Prediction intervals widen as the horizon grows. For d = 1 they widen without bound.
  • Short-horizon forecasts use recent values; long-horizon forecasts fall back to the mean or last level.

9.6 Strengths and limits

  • Strengths: a flexible, well-understood family; gives prediction intervals; handles short-term dependence.
  • Limits: needs stationarity (after differencing); no built-in seasonality (see Module 10); linear.

Module 10: SARIMA, SARIMAX and Fourier Terms

10.1 SARIMA

SARIMA adds seasonal AR, differencing and MA terms at the seasonal lag:

SARIMA(p, d, q)(P, D, Q)[m]

  • (p, d, q): ordinary parts (short-term dependence).
  • (P, D, Q): the same ideas at lags m, 2m, 3m, ….
  • m: the seasonal period (7 for weekly, 12 for monthly).

Typical example: SARIMA(1,0,1)(0,1,1)[7] = one seasonal difference (compare each day with the same weekday last week), plus short-term and seasonal MA terms.

model = SARIMAX(
    train,
    order=(1, 0, 1),
    seasonal_order=(0, 1, 1, 7),
    trend="n",               # no constant when differencing is used
)
fitted = model.fit(disp=False)
prediction = fitted.get_forecast(steps=28)

Choosing the seasonal orders

  • D: 1 if seasonality is strong and stable (seasonal strength > 0.64), otherwise 0. Rarely more than 1.
  • Q = 1 is very common after seasonal differencing (spike at lag m in the ACF).
  • P = 1 if the PACF shows a spike at lag m.
  • Keep P and Q at 0 or 1 in a first model.

10.2 Seasonal periods that are too long

SARIMA with m = 365 on daily data is impractical: the state space has hundreds of hidden states, fitting is very slow and unstable, and you need many years of data. Alternatives:

  • Fourier terms as external regressors (below).
  • STL + ARIMA (Module 11).
  • Model a lower frequency (weekly or monthly aggregates).

10.3 SARIMAX: adding external regressors

The X adds external variables (exogenous regressors) to the model: regression with ARIMA errors.

y(t) = β·x(t) + ARIMA errors

Use cases: holiday indicators, promotions, price, weather, weekday dummies.

Important: to forecast, you need the future values of x. Use variables you know in advance (calendar, planned promotions, holidays) or that you have forecast separately. Using a future value you would not have in production is leakage.

10.4 Fourier terms for long or multiple seasonalities

A smooth seasonal pattern with period P can be written as a sum of sines and cosines:

sin(2πk·t / P) and cos(2πk·t / P), for k = 1 … K.

  • Small K → smooth pattern; large K → flexible pattern. Choose K by AIC or validation.
  • Works for periods like 365.25 and for multiple seasonalities (add terms for each).
def fourier_terms(index, origin, period=365.25, K=2):
    t = (index - origin).days.to_numpy()
    columns = {}
    for k in range(1, K + 1):
        columns[f"sin_{k}"] = np.sin(2 * np.pi * k * t / period)
        columns[f"cos_{k}"] = np.cos(2 * np.pi * k * t / period)
    return pd.DataFrame(columns, index=index)

Use a fixed origin date so training and future dates are on the same time scale.

A common practical combination for daily data:

  • weekday dummy variables (6 dummies; one weekday is the reference) for the weekly pattern,
  • Fourier terms for the yearly pattern,
  • ARIMA errors (d = 0) for short-term dependence.
exog_train = fourier_terms(train.index, origin, K=2)
for day in range(1, 7):
    exog_train[f"dow_{day}"] = (train.index.dayofweek == day).astype(float)

fitted = SARIMAX(train, exog=exog_train, order=(1, 0, 0), trend="c").fit(disp=False)
# exog for the forecast period must be built the same way from future dates

10.5 Common mistakes

  • Forgetting to build the future regressors the same way as the training ones.
  • Including a regressor whose future value is unknown.
  • Differencing twice (once via d/D and once manually).
  • Searching too many seasonal orders.

Module 11: Other Classical Methods and Transformations

11.1 STL + ARIMA (or STL + ETS)

  1. Use STL to estimate the seasonal component.
  2. Remove it to get a seasonally adjusted series.
  3. Forecast the adjusted series with ARIMA or ETS.
  4. Add the seasonal pattern back (STL repeats the last seasonal cycle).
from statsmodels.tsa.forecasting.stl import STLForecast
from statsmodels.tsa.arima.model import ARIMA

stl_forecaster = STLForecast(train, ARIMA, model_kwargs={"order": (0, 1, 1)}, period=7)
fitted = stl_forecaster.fit()
forecast = fitted.forecast(len(test))

Pros: flexible seasonality, robust to outliers, easy to explain. Con: the seasonal pattern is assumed to stay as in the last cycle.

11.2 Theta method

A simple method that did well in forecasting competitions: it combines a long-term linear trend with a short-term smoothed level, after seasonal adjustment.

from statsmodels.tsa.forecasting.theta import ThetaModel
fitted = ThetaModel(train, period=7, deseasonalize=True, method="additive").fit()
forecast = fitted.forecast(len(test))

11.3 Regression on trend and season

from sklearn.linear_model import LinearRegression

X = fourier_terms(train.index, origin, K=3)
X["trend_days"] = (train.index - origin).days
regression = LinearRegression().fit(X, train)

Simple, transparent and quick, but it assumes the seasonal shape and trend are fixed forever.

11.4 Forecasting on a transformed scale

To forecast on a log scale and report on the original scale:

log_forecast = model_forecaster(np.log1p(history), index)
forecast = np.expm1(log_forecast)           # also transform interval bounds

Remember: the back-transformed point forecast is closer to the median than the mean, so it can be slightly low.

11.5 Forecast combinations

Averaging the forecasts of several good, different models often beats the best single model, and reduces the risk of picking the wrong one. A simple average works well.

Module 12: Machine Learning for Forecasting

12.1 Turning forecasting into supervised learning

Build a table where each row is a time point, the target is y(t), and features are things known before t.

Feature type Examples
Lag features y(t−1), y(t−7), y(t−14), y(t−28)
Rolling features mean and std of the last 7 or 28 values (computed on shifted data)
Calendar features weekday, month, day of year, holiday, Fourier terms
External features planned promotions, price, forecasted weather 
def make_features(y, lags=(1, 2, 3, 7, 14, 21, 28)):
    features = pd.concat({f"lag_{k}": y.shift(k) for k in lags}, axis=1)
    features["rolling_mean_7"] = y.shift(1).rolling(7).mean()    # shift first: no leakage
    features["weekday"] = y.index.dayofweek
    features["month"] = y.index.month
    return features.dropna()

Leakage warning: a rolling mean must be computed on data shifted by 1 (or more) so it does not include the value being predicted.

12.2 Models

  • Random Forest: averages many decision trees; robust, little tuning.
  • Gradient boosting (scikit-learn GradientBoostingRegressor, LightGBM, XGBoost): usually the strongest tabular model; needs some tuning.
  • Linear models (Ridge, Lasso): good with many features and a clear trend.

12.3 Multi-step forecasting strategies

Strategy How Pros Cons
Recursive predict one step; feed the prediction back as the next lag one model; simple errors compound over the horizon
Direct a separate model for each horizon h no error compounding many models
Multi-output one model predicts all h values efficient needs suitable model 
def recursive_forecast(fitted, history, index, lags):
    recent = list(history.iloc[-max(lags):])
    predictions = []
    for date in index:
        row = {f"lag_{k}": recent[-k] for k in lags}
        # add calendar features for `date` here
        x = pd.DataFrame([row])
        y_hat = float(fitted.predict(x)[0])
        predictions.append(y_hat)
        recent.append(y_hat)               # the prediction becomes the next lag
    return pd.Series(predictions, index=index)

12.4 Limits of tree-based models

  • They cannot extrapolate: a tree predicts values it has seen. A trending series that leaves its historical range will be under-forecast. Fixes: forecast the differences or detrend first, or combine with a linear trend.
  • Recursive forecasts can flatten towards the average at long horizons.
  • They need enough history for lags and features.

12.5 Validation and tuning

Use TimeSeriesSplit (expanding window), never ordinary k-fold. Tune hyperparameters inside the training data. Do not tune on the test window; if you do, you need a further untouched test period.

from sklearn.model_selection import TimeSeriesSplit, GridSearchCV
from sklearn.ensemble import GradientBoostingRegressor

search = GridSearchCV(
    GradientBoostingRegressor(random_state=42),
    param_grid={"n_estimators": [100, 200], "max_depth": [2, 3]},
    cv=TimeSeriesSplit(n_splits=4, test_size=28),
    scoring="neg_mean_absolute_error",
)

12.6 When ML helps

  • Many external variables with nonlinear effects.
  • Many related series (one global model across series).
  • Complex calendar effects.

For a single clean seasonal series, classical models are often just as good or better, and easier to explain. The right question is "does it beat a seasonal baseline in a fair test?", not "is it modern?"

Module 13: Uncertainty and Comparing Models

13.1 Prediction intervals

A point forecast is the center of a distribution. A 95% prediction interval says: if the model assumptions hold, about 95% of future values should fall in this range.

For many models, an approximate interval is forecast ± 1.96 · σ(h), where σ(h) is the forecast error standard deviation at horizon h. It grows with the horizon.

Sources of uncertainty:

  1. random noise in future values,
  2. uncertainty in the model parameters,
  3. uncertainty about the model itself,
  4. changes in the process (structural breaks).

Intervals from a model usually include only the first (and sometimes the second), so they tend to be too narrow.

Interval methods

  • Model-based: from ARIMA, ETS (assume normal, constant-variance errors).
  • Empirical: take quantiles (2.5%, 97.5%) of past forecast errors and add them to the point forecast. Needed for models without native intervals (machine learning, Theta). Better when done per horizon.
  • Bootstrap: resample residuals to simulate future paths.
  • Quantile regression: train models to predict quantiles directly.

13.2 Checking interval quality

Coverage: the share of actual values inside the interval. A 95% interval should cover about 95%.

inside = ((actual >= lower) & (actual <= upper)).mean()
print(f"Coverage: {inside * 100:.1f}%")
  • Much below 95%: intervals are too narrow (overconfident).
  • Much above 95%: intervals are too wide (uninformative).
  • With few evaluation points, coverage is noisy.

13.3 Is model A really better than model B?

With one test window, a 2% difference in RMSE can be luck. Two tools:

Diebold-Mariano (DM) test

  • H0: both models have equal expected loss (for example squared error).
  • Uses the differences in squared errors, with a variance estimate that accounts for autocorrelation (errors at multi-step horizons are autocorrelated).
  • Small p-value: one model is significantly more accurate.
  • Large p-value: the data cannot tell them apart; treat the models as tied.

Practical habits

  • Evaluate on several windows (rolling origin).
  • Report differences with their uncertainty.
  • Beware multiple comparisons: testing many models against one reference will produce some "significant" results by chance.
  • Prefer the simpler model when the difference is not significant.
  • Consider combining tied models.

13.4 Communicating a forecast

  • Show the point forecast and the interval.
  • State the horizon, the metric and the evaluation method.
  • State the assumptions (no major events, stable behaviour).
  • Say what the forecast cannot know (promotions, outages, news).

Module 15: Doing a Complete Project

15.1 Project checklist

Data

  • Dataset has a date column, a numeric target, and enough history (at least 2–3 full seasonal cycles).
  • Source and licence documented.
  • Datetime index, sorted, no duplicate dates, frequency verified.
  • Abnormal values flagged; missing values handled with a stated reason.
  • If there are several files, overlaps and consistency checked.

Analysis

  • Chronological split created before deep exploration.
  • Plots: full series, rolling mean/std, calendar patterns, decomposition.
  • Stationarity test, differencing decisions by rules stated in advance.
  • ACF/PACF interpreted.

Modelling

  • Seasonal baselines first.
  • A small, explainable model search (not hundreds of combinations).
  • Several model families (baseline, classical, ML).
  • No test data used for fitting or selection (or the test period clearly documented as used for selection).

Evaluation

  • Multiple metrics, with the horizon stated.
  • Rolling-origin evaluation if the data allows.
  • Residual diagnostics.
  • Significance test or an honest statement that small differences are weak evidence.

Forecast and reporting

  • Future forecast with an interval.
  • Limitations written down.
  • README with results, how to run, repository structure.
  • Results table filled with real numbers from the final run.

15.2 Common mistakes (and what they cost)

Mistake Consequence
Random train/test split leakage; inflated scores
Skipping baselines no way to know if a model adds value
Over-interpreting a short test window wrong model chosen
Choosing a model after seeing the test result without saying so optimistic claims
Over-differencing noisy forecasts
Searching hundreds of orders overfitting; unexplainable model
Using MAPE on data near zero or on Celsius misleading numbers
Ignoring a suspicious data row distorts models that depend on recent values
Reporting a forecast without an interval false certainty
Forgetting future values of regressors unusable model

15.3 Lessons from the two practice projects

These come from the two projects built alongside this course (daily temperature in Delhi, and daily website visitors).

  1. Check the data before the models. One placeholder-like row at the end of a training set pushed a Naive forecast's error up sharply. Overlapping dates between files must be inspected.
  2. Model the seasonality at the right scale. Yearly seasonality in temperature, weekly in website traffic. Models without a seasonal component performed far worse.
  3. A short test window gives weak evidence. The ranking of the top models changed after fixing one training row, which is a reminder to use rolling-origin evaluation and significance tests.
  4. Be honest about limitations. Every model, interval and test window has assumptions.
